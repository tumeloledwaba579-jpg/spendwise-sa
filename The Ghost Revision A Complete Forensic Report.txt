## 🔍 **The Error Message**
```bash
ERROR [alembic.util.messaging] Can't locate revision identified by '2fbb3db98600'
FAILED: Can't locate revision identified by '2fbb3db98600'
```

This error appeared every time we tried to run:
- `alembic upgrade head`
- `alembic stamp base`
- `alembic revision --autogenerate`

## 🏆 **The Final Solution**

```powershell
# 1. Kill local PostgreSQL (as Administrator)
taskkill /F /PID 6400

# 2. Reset Docker completely
# Docker Desktop → Troubleshoot → Reset to factory defaults

# 3. Create fresh containers
docker-compose up -d postgres redis

# 4. Run migrations (finally works!)
alembic upgrade head
```

## 📊 **Root Cause Analysis**

### **Primary Cause**
A **local Windows PostgreSQL installation** was running as a system service, invisible to our Docker-focused debugging. This instance:
- Had an `alembic_version` table with revision `2fbb3db98600`
- Was auto-restarting whenever we tried to kill it
- Was prioritized over Docker containers due to port conflict

### **Contributing Factors**

| Factor | Impact |
|--------|--------|
| **Two PostgreSQL instances** | Confusing which DB was being accessed |
| **Docker context corruption** | Made it appear Docker was the problem |
| **Windows service permissions** | Couldn't stop service without admin rights |
| **Alembic's silent fallback** | Connected to any available DB on port 5432 |

## 🛡️ **Prevention Checklist**

### **Before Starting a New Project**
```powershell
# Check for existing PostgreSQL installations
Get-Service | Where-Object { $_.Name -like "*postgres*" }

# Check what's using port 5432
netstat -ano | findstr :5432

# List all Docker containers
docker ps -a
```

### **When Using Docker**
```powershell
# Always use container names explicitly
docker exec -it spendwise-postgres psql -U postgres

# Check Docker context
docker context ls

# Verify which PostgreSQL you're connecting to
docker exec -it spendwise-postgres psql -U postgres -c "SELECT inet_server_addr();"
```

### **When Debugging Alembic Issues**
```powershell
# Enable debug logging
$env:ALEMBIC_DEBUG = "1"
alembic upgrade head --verbose

# Check alembic_version directly
docker exec -it spendwise-postgres psql -U postgres -d spendwise_db -c "SELECT * FROM alembic_version;"
```

## 📝 **Epilogue**

The ghost revision `2fbb3db98600` was never in our code, our migrations, or our Docker containers. It was hiding in a **local Windows PostgreSQL installation** that was installed months ago and forgotten. Every time we reset Docker, the local PostgreSQL would happily serve the ghost revision, making us believe our fixes weren't working.

**The lesson:** Always check for multiple instances of critical services, especially databases. A single port can hide a world of confusion.
