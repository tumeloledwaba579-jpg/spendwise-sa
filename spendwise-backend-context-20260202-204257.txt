[4] AUTHENTICATION & AUTHORIZATION
═══════════════════════════════════════════════════════════════════

JWT Token Flow:
1. User registers → POST /api/v1/auth/register
2. User logs in → POST /api/v1/auth/login → receives JWT token
3. Frontend stores token in localStorage
4. All subsequent requests include: Authorization: Bearer <token>
5. Backend validates token using get_current_user dependency

Token Details:
  - Algorithm: HS256
  - Expiry: 30 minutes (configurable)
  - Payload: { sub: user_id, exp: timestamp }
  - Secret: Stored in environment variable

Protected Endpoints:
  - ALL endpoints except /auth/register and /auth/login require authentication
  - Token must be valid and not expired
  - User must be active (is_active = True)

PAGINATION:

  400 Bad Request: { detail: "Error message" }
  401 Unauthorized: { detail: "Not authenticated" }
  404 Not Found: { detail: "Resource not found" }
  422 Validation Error: { detail: [{loc, msg, type}, ...] }
  500 Server Error: { detail: "Internal server error" }

SUCCESS RESPONSES:
  200 OK: Resource(s) returned
  201 Created: Resource created
  204 No Content: Resource deleted
